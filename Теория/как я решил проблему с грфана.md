## Что у тебя сейчас на диске

Сейчас есть **два варианта JSON-файла**:

1. `/tmp/do9-dashboard-fixed.json` — то что **ты руками импортировал** в Grafana (с заменёнными UID-ами `PBFA97...` и `P8E80...`)
2. `~/prometheus-loki-grafana-swarm/src/grafana/dashboards/do9-dashboard.json` — **исходный шаблон** с плейсхолдерами `prometheus`/`loki`

**Для git-репо нужен второй вариант** (без захардкоженных UID). Почему — UID-ы datasources **уникальны для каждой Grafana**. Если кто-то импортирует твой dashboard в свою Grafana, его UID будут другие, и дашборд снова покажет `No data`.

## Лучшее решение — экспортировать актуальный из Grafana и удалить UID

Это самый правильный способ. Grafana отдаёт текущее состояние дашборда (с **всеми** правками, которые ты в нём делал), затем мы выкидываем привязку к датасорсам и сохраняем в репо.

```bash
# 1. Экспортировать актуальный дашборд из Grafana
curl -s -u admin:admin "http://192.168.56.10:3000/api/dashboards/uid/do9-main" \
    > /tmp/dashboard-raw.json

# 2. Убрать обёртку (Grafana возвращает {meta:..., dashboard:...}) и подменить datasources обратно на плейсхолдеры
python3 << 'EOF'
import json

with open('/tmp/dashboard-raw.json') as f:
    data = json.load(f)

# Достаём только сам dashboard
dash = data['dashboard']

# Сбрасываем id (чтобы не было конфликта при импорте на другой системе)
dash['id'] = None
dash['version'] = 1

# Подменяем UID datasources на плейсхолдеры
def replace_uid(obj):
    if isinstance(obj, dict):
        if 'uid' in obj and 'type' in obj:
            if obj['type'] == 'prometheus':
                obj['uid'] = 'prometheus'
            elif obj['type'] == 'loki':
                obj['uid'] = 'loki'
        for v in obj.values():
            replace_uid(v)
    elif isinstance(obj, list):
        for v in obj:
            replace_uid(v)

replace_uid(dash)

# Сохраняем
with open('/home/s/prometheus-loki-grafana-swarm/src/grafana/dashboards/do9-dashboard.json', 'w') as f:
    json.dump(dash, f, indent=2, ensure_ascii=False)

print("Saved to ~/prometheus-loki-grafana-swarm/src/grafana/dashboards/do9-dashboard.json")
EOF

# 3. Проверить
ls -lh ~/prometheus-loki-grafana-swarm/src/grafana/dashboards/do9-dashboard.json

# 4. Убедиться что UID подменились правильно
grep -E '"uid"' ~/prometheus-loki-grafana-swarm/src/grafana/dashboards/do9-dashboard.json | sort | uniq -c
```

В выводе должно быть:
```
   1 "uid": "do9-main"        ← это UID самого дашборда (нужен)
  14 "uid": "prometheus"      ← плейсхолдер для Prometheus
   2 "uid": "loki"             ← плейсхолдер для Loki
```

# Найдена точная причина обоих провалов!

## Корень проблемы — старые логи отвергаются Loki

Смотри ключевую строку:
```
"entry with timestamp 2026-05-15 08:46:59 ignored, 
reason: 'entry too far behind, 
oldest acceptable timestamp is: 2026-05-15T10:10:59Z'"
```

Promtail отправляет логи **с timestamp 08:46** (старые), а Loki по умолчанию принимает только записи **не старше 1 часа**. Promtail хранит `positions.yaml` со старыми смещениями в файле, поэтому пытается «доотправить» древние логи и Loki их **отвергает все скопом**. Из-за этого никаких реальных логов в Loki **не попадает**.

Это типичный после-рестарта баг — Promtail помнит, где остановился, но logs за это время уже закончились а cursor стоит в прошлом.

## Решение — два шага

### Шаг 1 — Удалить positions у Promtail и перезапустить

`positions.yaml` лежит в volume promtail, и не очищается между deploy. Удаляем его и перезапускаем:
